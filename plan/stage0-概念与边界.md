# 阶段 0 · 概念与系统边界（第 1–4 天）

> 目标：能用自己的话解释什么是 agent harness，并把模型、harness、任务环境与评测器画成四个不同的盒子。

主线资料：[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)、[Harness engineering](https://openai.com/index/harness-engineering)。先看结构图和实例，暂时跳过陌生 API。

## 核心概念

一个最小 agent 循环是：收到目标 → 模型选择回答或工具动作 → harness 校验并执行 → 环境返回观察 → 模型继续或停止。Harness 决定模型能看见什么、能调用什么、每一步如何记录，以及什么时候必须停下。不同文章对 harness 的边界略有差异；研究时先写出自己的操作性定义。

| 名称 | 本课程中的边界 | 例子 |
| --- | --- | --- |
| 模型 | 把上下文映射成下一步输出 | 语言模型或模拟策略 |
| Harness | 组织循环、工具、状态、约束与日志 | 工具路由、预算、检查点 |
| 任务环境 | 接受动作并产生结果的世界 | 文件夹、网页、测试仓库 |
| 评测器 | 判断任务是否完成及代价 | 单元测试、规则评分 |

## 任务清单

### ☐ 0-1 用一张图解释 agent 循环

- 阅读主线资料的开头和架构部分，画出“目标—模型—动作—工具—观察—停止”的箭头图；在每条箭头旁写明数据是什么。
- 思考题：只有一次模型调用、没有反馈循环的应用，何时仍可称为 agent？请写出你的判定标准。
- **完成标志**：能在 2 分钟内不看资料解释一个工具调用回合，并给出一次可能的失败位置。

### ☐ 0-2 列出 harness 的可控旋钮

- 从主线资料各找一个例子，整理至少 8 个可由工程师修改的旋钮，例如工具说明、动作校验、步数预算、上下文选择、持久状态和验收规则。
- 将旋钮标为“影响可见信息”“影响可执行动作”或“影响反馈与停止”。允许一个旋钮落在多类。
- 思考题：换更强的模型与更改工具描述，分别改动了图中的哪个盒子？
- **完成标志**：保存一张四列清单，列出旋钮、所属盒子、预期作用、潜在副作用。

### ☐ 0-3 观察一次真实长任务的交接

- 阅读 [Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)，只追踪“初始化—逐步工作—留下交接记录—下一次恢复”这一条线。
- 用 150 字复述为什么仅压缩对话不一定足够，并指出进度文件和版本历史分别保留了什么信息。
- 思考题：如果下一次运行误以为任务已经完成，应该由哪种证据纠正它？
- **完成标志**：画出两次会话之间的信息交接图，并标出丢失状态的风险。

### ☐ 0-4 建立术语卡与第一版研究问题

- 为 agent、workflow、harness、trajectory、state、memory、evaluation 各写一句定义和一个反例。
- 写下一个想研究的问题，例如“从失败轨迹自动改写工具说明，能否提高新任务成功率而不损害旧任务？”
- 自测：不看资料，能否解释“性能改善”可能来自模型、任务分布、harness 或评分器的变化？
- **完成标志**：形成 7 张术语卡和一段可被实验检验的问题陈述。
