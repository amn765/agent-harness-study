# 阶段 5 · 持续学习与自进化（第 21–24 天）

> 目标：区分“从反馈更新记忆或策略”和“真正改变模型权重”，并实现一个受约束的 harness 更新循环。

主线资料：[Reflexion](https://arxiv.org/abs/2303.11366)、[Continual Harness](https://arxiv.org/abs/2605.09998)、[EVOHARNESSBENCH](https://arxiv.org/abs/2609.04280)。选读：[SkillLearnBench](https://arxiv.org/abs/2604.20087)、[Do Agent Optimizers Compound?](https://arxiv.org/abs/2607.14004)。先读摘要、方法图、实验设置与局限，详细公式可留到第二轮。

## 核心概念

“自进化”不是让 agent 任意修改自身。一个可研究的循环是：收集轨迹 → 用外部可验证反馈定位失败 → 提出一个可审查的候选改动 → 在开发任务上选择 → 用冻结的旧任务和新任务回归测试 → 保留或回滚。候选改动可以是提示、工具说明、技能或记忆检索规则；第一轮固定模型权重。

| 更新位置 | 例子 | 主要风险 |
| --- | --- | --- |
| 情节记忆 | 保存失败与修正摘要 | 错误记忆累积、检索污染 |
| 技能或提示 | 修改工具使用步骤 | 对训练任务过拟合 |
| 工具与路由 | 新增工具、调整说明 | 旧工具选择退化 |
| 模型权重 | 微调或强化学习 | 成本与归因更复杂，本轮暂不实现 |

## 任务清单

### ☐ 5-1 阅读三篇论文并建立比较表

- 对 Reflexion、Continual Harness、EVOHARNESSBENCH 各写五项：更新什么、反馈来自哪里、何时更新、如何评测、有什么失败模式。区分论文报告的结果与自己的推测。
- 特别记录 EVOHARNESSBENCH 中“harness 扩展也可能损害已有能力”的问题设定；不要把工具越多等同于性能越好。
- **完成标志**：一张三行比较表和一段 200 字研究空白陈述。

### ☐ 5-2 实现受约束的经验记忆

- 对评测失败轨迹生成结构化记录：任务类型、失败步骤、可验证证据、建议修正、适用条件。先手写 3 条经验，不让模型自动编造事实。
- 写 `retrieve_memory(task, records)`，只返回匹配任务类型且经过验证的记录；限制条数与总字符数，并记录具体使用了哪条经验。
- 思考题：一条经验在任务 A 有效，为什么可能伤害任务 B？
- **完成标志**：一次运行能显示被检索的经验 ID，并能关闭检索作对照。

### ☐ 5-3 ⭐ 建立候选更新、回归测试与回滚

- 只允许修改一个白名单字段，例如工具描述中的一条提示或检索规则。每次候选更新生成版本号和差异说明，不直接覆盖基线。
- 候选先在开发任务上跑，再在旧任务和新任务上跑。预先写接受规则，例如“开发成功数不降、旧任务成功数不降、新任务至少增加 1，且总步骤增幅小于 20%”；未通过就回滚。
- 自测：若反馈完全来自系统自身，没有独立可验证信号，接受规则会被什么偏差污染？
- **完成标志**：至少演示一次接受或回滚，并保存改动前后配置和逐任务结果。

### ☐ 5-4 检查遗忘、迁移与成本

- 制作时间轴：版本 0 → 接收第一批任务 → 更新 1 → 接收第二批任务 → 更新 2。每一步都重新跑冻结的旧任务与留出的新任务。
- 画出每版旧任务成功数、新任务成功数与平均步骤数。若使用真实模型且输出不稳定，固定模型版本并做多次运行，报告方差。
- **完成标志**：能说明“持续改善”“只在旧任务改善”“遗忘”“成本过高”分别对应哪一组数值变化。
