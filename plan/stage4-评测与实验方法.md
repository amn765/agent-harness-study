# 阶段 4 · 评测与实验方法（第 17–20 天）

> 目标：把“看起来更聪明”变成可复现的任务结果、成本与失败类别。

主线资料：[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)、[Harness engineering](https://openai.com/index/harness-engineering/)。观察评测任务、环境、评分器、轨迹之间的关系。

## 核心概念

成功率只是一个指标。还要报告完成所需步骤、工具错误、预算耗尽、耗时或 token 成本。对自进化研究，应把旧任务保持率和新任务适应率并列；只看更新后的训练任务会造成误判。

## 任务清单

### ☐ 4-1 冻结任务集与评分规则

- 将任务扩展到 12 个：6 个开发任务、3 个保留旧任务、3 个只在评测时使用的新任务。为每个任务写机器可验证的预期结果，并记录任务版本。
- 区分“模型说完成”“环境真实达标”“评分器判成功”。人工抽查 3 条轨迹，找出评分器可能误判的情况。
- 思考题：如果评测任务参与了 prompt 修改，它还能当作独立测试集吗？
- **完成标志**：任务文件与评分函数冻结，能单独运行并返回清晰的通过或失败理由。

### ☐ 4-2 写统一评测脚本

- 编写 `evaluate.py`，对每个任务重建初始环境，调用同一个 `run`，保存配置哈希、任务 ID、状态、得分、步数、拒绝次数和轨迹路径。
- 用 CSV 输出一行一个任务；同时打印汇总。先使用确定性的模拟模型，验证同一配置重复运行的结果一致。
- **完成标志**：两次运行可比较，并能追溯到相同的任务与 harness 配置。

### ☐ 4-3 计算效果、成本与保持率

- 计算成功率 `成功任务数 / 总任务数`、平均步骤数和失败类型分布。旧任务保持率定义为“更新后仍成功的旧任务数 / 更新前成功的旧任务数”，并同时报告旧任务总体成功率。
- 若分母为 0，标记为“不适用”，不要输出 0%。记录新任务成功率与额外工具调用数。
- 思考题：某配置成功率多 1/12，但平均步骤翻倍，怎样描述这个取舍？
- **完成标志**：完成一张含原始计数与分母的指标表，不只给百分比。

### ☐ 4-4 做一个单变量消融

- 固定模型、任务和评分器，只更改一个 harness 开关，例如是否显示工具错误说明，或是否使用交接摘要。运行 A/B 两组并保存原始轨迹。
- 逐条比较状态翻转的任务：从失败变成功、从成功变失败、保持不变。样本只有 12 个，结论写成探索性观察，不声称统计显著。
- **完成标志**：提交一页实验记录，包含配置差异、任务逐项结果、成本、反例和可能混杂因素。

## 阶段里程碑

你拥有可重复执行的评测管线，并能用轨迹解释某个 harness 改动为何改善或损害结果。
